# Build Package Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Nova's Content ▸ Build dashboard as the public, English-only NuGet package `Esatto.Umbraco.Backoffice.Build` 1.0.0, with a documented `build-info.json` format and a reference CI script.

**Architecture:** A Razor-SDK package mirroring SEO Health: a small server part (stamp reader, local git reader, package catalog, one service, one controller, a composer) and a TypeScript/Vite client (one dashboard element plus pure, unit-tested helpers) built into `wwwroot/App_Plugins/Esatto.Umbraco.Backoffice.Build`. The CI side is a dependency-free Node script that lives in the repo (not in the nupkg), tested with `node --test`; one shared fixture ties its output to the C# reader.

**Tech Stack:** .NET 10 / Umbraco 18, xUnit + NSubstitute, TypeScript + Vite + Lit + Vitest, Node 20+ (`node:test`), MinVer.

**Spec:** `docs/superpowers/specs/2026-11-20-build-design.md` (read it first; this plan argues from it).

- Folder = csproj = PackageId = RootNamespace = AssemblyName = `Esatto.Umbraco.Backoffice.Build`; tests `Esatto.Umbraco.Backoffice.Build.Tests`; Umbraco 18 only; `net10.0`.
- The root namespace begins `Esatto.Umbraco.*`, so never write an inline `Umbraco.Cms…` name: add a `using` and use the short type name.
- Packaging mirrors the SEO Health csproj: Razor SDK, `StaticWebAssetBasePath=/`, the `BuildBackofficeClient` target, `Umbraco.Cms.Api.Management` and `Umbraco.Cms.Web.Common` minimum `18.0.0`, `AutoPush` off by default, `InternalsVisibleTo` `Esatto.Umbraco.Backoffice.Build.Tests`. Tags `umbraco;umbraco-marketplace;umbraco-18;backoffice;build;deployment;ci`. Source link: `RepositoryUrl` `https://github.com/carl-schele-esatto/Esatto.Packages`, `PackageProjectUrl` `https://github.com/carl-schele-esatto/Esatto.Packages/tree/main/Esatto.Umbraco.Backoffice.Build`, `RepositoryType` git. Version from MinVer tag `Esatto.Umbraco.Backoffice.Build-1.0.0`. `dotnet pack` is warning-free.
- API: `GET esatto/build-info` (`VersionedApiBackOfficeRoute`), `ApiExplorerSettings(GroupName = "Esatto Build")`, `Authorize(Policy = AuthorizationPolicies.SectionAccessContent)`, camelCase JSON (`JsonSerializerDefaults.Web`).
- Configuration section `Esatto:Build`: `FilePath` (default `build-info.json`, relative to the content root) and `Packages` (assembly names; a trailing `*` matches a family; **adds to** the defaults).
- Manifest: dashboard alias `Esatto.Umbraco.Backoffice.Build.Dashboard`, element `esatto-build-dashboard`, label "Build", pathname `build`, weight `-200`, Content section only. Localization extension alias `Esatto.Umbraco.Backoffice.Build.Localization.En`, culture `en`; **no other language file**.
- English only: user-facing text is a key `esattoBuild_<key>` from `Client/src/lang/en.ts`; comments, log messages, test names, README and script output are English. No Swedish anywhere.
- Dates use `Intl.DateTimeFormat(undefined, …)` (the browser's locale), never a hard-coded locale; the relative phrase ("10 days ago") is English.
- A URL from the stamp becomes a link only if it is `http:`/`https:`, always with `rel="noopener"`; otherwise plain text.
- The host app's version comes from `Assembly.GetEntryAssembly()`, never the package's own assembly. Local git is read only when `IHostEnvironment.IsDevelopment()` **and** there is no stamp.
- No real esatto.se data in this public repo: fixtures, test data and screenshots are synthetic (`example.com`, invented names).
- Never `git commit`, tag, push or publish without Carl's explicit approval: every "Commit" step is a checkpoint where you ask first. Carl runs `dotnet nuget push`.
- Work in a worktree on `feature/build-package` created from `main`, **not** on `feature/seo-report-package` (it holds uncommitted SeoReport work).

## Review Focus

Failure modes the spec implies but its own tests don't exercise; each has its test in the named task.

1. **Shallow CI checkout** (GitHub Actions checks out one commit by default): the script must say so (`fetch-depth: 0` / `fetchDepth: 0`) and still write a valid stamp instead of failing or silently listing one commit. Task 6.
2. **`--out` into a folder that doesn't exist yet**: created, not an `ENOENT` crash. Task 6.
3. **A stamp saved with a UTF-8 BOM** (PowerShell `Out-File` on a Windows runner): read normally. Task 1.
4. **The same assembly matched by the defaults and by `Esatto:Build:Packages`, blank entries, entries that aren't loaded**: listed once, ignored, skipped; never an exception. Task 3.
5. **An optional stamp field with the wrong JSON type** (`"changes": []`, `"builtAtUtc": 123`): one warning and no pipeline build, never an exception reaching the backoffice. Task 1.
